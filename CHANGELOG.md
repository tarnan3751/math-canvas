## 0.9.1 — 2026-11-04

### Notes

- 0.9.0 was tagged but its Windows and Linux installers never built: on x86-64 one pooled confidence
  interval printed two of its sixteen digits differently than on Apple Silicon, where the corpora
  were recorded, because the incomplete beta function called `Math.exp` and `Math.log`, whose
  HotSpot stubs differ by architecture in the last place. The engine's numeric paths that print now
  call `StrictMath`, which is specified bit for bit, and a test keeps it so. 0.9.1 is the same
  release with that fix, a parser fix for a quantity whose magnitude is a product (`3°_m` now
  round-trips), the installers' shortcuts and menu entries, the per-platform install steps in the
  README, and the documentation site, published to GitHub Pages with each release from this one on.

## 1.0.0 — 2026-11-04

### Notes

- Programs: a cell or script may hold `if … then … else … end`, `for x in a..b … end`, `while … end`
  and `function f(x) … return … end`; `print(e)` shows a value from inside a program; a run has a
  budget of a million steps and a call depth of a thousand, and `steps` narrates it. The words
  `end`, `do`, `step`, `break`, `continue` and `global` and the function `print` are reserved
  now: a session saved by an earlier release that used them as names opens with them renamed to
  `v_…` (session version 5).
- `help(name)` opens the Help window on that entry in the app and prints it in the CLI; every
  example in the window runs when clicked. The documentation site is attached to the release as
  a zip and deployed to GitHub Pages by the release workflow once Pages is enabled.
- The update check is off by default; when turned on in Settings it makes one request to GitHub
  Releases on launch and shows a one-line notice. No other network call is made. The settings
  file is at version 5 (the update check and the language).
- The application has an icon, and its name is the `appName` property of the app's build.
- Fixed since 0.9.1: `log 2 − log 4` and the other simplifier gaps recorded in the plan, a sum's
  sign from its symbols' bounds (`∫∫` over the unit disc evaluates), a bound at `log 2`, relations
  kept as typed inside `solve` and `diophantine`, Bernoulli equations of fractional order, `atan`
  inverted in `dsolve`, `laplace` of an unknown function and the repeated-quadratic inverses, and
  the flaky UI tests.
- The installers are unsigned; the README's install section gives the Gatekeeper and SmartScreen
  steps.

## 0.9.0 — 2026-11-03

### Notes

- One hundred and thirty new builtin functions and commands across number theory, discrete
  mathematics, statistics, units, bases, bitwise operations and finance (`isprime`, `ifactor`,
  `powmod`, `crt`, `diophantine`, `rsolve`, `truthtable`, `mean`, `stdev`, `normalcdf`, `invnorm`,
  `binompdf`, `linreg`, `ttest`, `chi2test`, `tinterval`, `convert`, `hex`, `bitand`, `pv`, `pmt`,
  `tvm` among them; `docs/language.md` §12 lists them). A builtin name cannot be defined, so a
  worksheet or script that defined a function of one of these names now gets an error at that
  definition and should rename it; `mean`, `range`, `mode`, `sort`, `gamma` and `beta` are the
  likeliest.
- `mod` is an infix operator (`17 mod 5`); `x mod(5, 3)` no longer means `x·mod(5, 3)`. `and`,
  `or`, `not`, `xor` and `implies` (`∧ ∨ ¬ ⊕ ⟹`) are boolean operators; `∪`, `∩`, `\` and `∈`
  work on sets.
- A name may no longer start with an underscore: `_m`, `_km/_h` are units. A session saved by
  an earlier release that used such names opens with them renamed to `v_…` (session version 4).
- `0xff`, `0b1011` and `0o17` are integer literals; `hex`, `bin`, `oct` and `base` show an
  integer in another base.
- Calculus, statistics and `odesolve` work in radians in every angle mode; the trigonometric
  functions of an angle quantity (`sin(30 _deg)`) too.
- A value from the distribution provider is marked numeric and printed to 16 digits; a
  quantile the provider cannot place to its accuracy leaves the call with a note.

## 0.8.0 — 2026-11-03

### Notes

- Thirteen new builtin functions: `grad`, `jacobian`, `hessian`, `divergence`, `curl`,
  `laplacian`, `lagrange`, `lineintegral`, `surfaceintegral`, `laplace`, `ilaplace`, `dsolve`
  and `odesolve`. A builtin name cannot be defined, so a worksheet or script that defined a
  function of one of these names now gets an error at that definition and should rename it.
  `grad` is no longer a reserved name.
- The order of `diff` is a literal (or an expression without names) that evaluates to a positive
  integer; a name in the third or a later position is a variable of differentiation, so
  `diff(f, x, y)` is the mixed partial `∂²/∂y∂x f`. A worksheet that wrote
  `n := 2; diff(x^3, x, n)` now differentiates in `n` (and gets `0`); write `diff(x^3, x, 2)`.
  `diff(f, x, e)` is now a parse error.
- `'` and `′` after an identifier form a derivative name (`y'(x)`, `f''(2)`); `30°15′` is still
  an angle. Calculus, `dsolve` and `odesolve` included, works in radians in every angle mode.
- Constants of integration `C₁, C₂, …` are fresh names recorded as `C₁ ∈ ℝ`, and take a value
  from `subs` or a function parameter as `k` does.
- A definite integral's value is now folded as evaluation would leave it (`log(15.625)` in a
  value becomes a decimal), and a definite integral with equal bounds is 0.
- An iterated integral under `numeric` is computed by nested Gauss–Kronrod in `double`, to the
  digits two runs agree on and at most twelve; the step says so.
- Hipparchus ODE (Apache-2.0; its licence texts are identical to Core's, `legal/`) now ships,
  merged into the runtime image.
- A session saved with fields, contour plots, solution curves or 3D objects on the canvas does
  not open in 0.7.x (an unknown object kind); every earlier session opens unchanged in 0.8.0.
  The 3D camera is saved with the session; the 3D toggle is not.
